# Image Magic — допечатная проверка и подготовка заказов

Image Magic проверяет растровые макеты перед печатью, группирует `face/back` по номеру заказа, безопасно корректирует небольшие отклонения размеров, создаёт итоговые PDF, превью и интерактивный HTML-отчёт.

Поддерживаемые входные форматы: `JPG`, `JPEG`, `TIFF`, `PNG`. Форматы `PSD`, `BMP`, `HEIC` и `HEIF` исключаются из обработки и направляются в `Troubles` с объяснением причины.

## Возможности

- разбор размера, цветности, клиента, заказа и стороны из имени файла;
- группировка односторонних и двусторонних заказов;
- проверка физического размера, DPI, количества кадров TIFF и цветовой модели;
- минимум 300 DPI после любой коррекции;
- безопасное пропорциональное масштабирование без растягивания сторон;
- центральная обрезка небольшого избытка макета;
- подтверждение спорных коррекций перед созданием PDF;
- RGB/sRGB отображается как предупреждение и сохраняется без преобразования в CMYK;
- одинаково допустимы размеры `50×90` и `90×50` — порядок сторон в имени не задаёт верх макета;
- контроль ориентации `face/back` без автоматического поворота одностороннего заказа;
- итоговая проверка количества, порядка и размера страниц PDF;
- превью с линиями реза и безопасной зоны;
- HTML-отчёт с ошибками, предупреждениями, параметрами коррекции и визуальной проверкой ориентации;
- шаблонные причины возврата из справочника с поиском и множественным выбором отдельно для каждого заказа;
- формирование и копирование готовых комментариев возврата по выбранным заказам;
- копирование отклонённых заказов в `Troubles` без изменения оригиналов;
- сохранение истории проверок в SQLite через SQLAlchemy.
- report-only проверка итогового PDF через PitStop Server с отдельным
  отображением проблем PDF и технических сбоев;

## Политика размеров

Размер изделия берётся из имени файла, после чего к ширине и высоте добавляется 4 мм вылетов.

- отклонение до 0,1 мм включительно считается погрешностью метаданных;
- отклонение/центральная обрезка от 0,1 до 0,5 мм корректируется автоматически с предупреждением;
- центральная обрезка от 0,5 до 2 мм требует подтверждения пользователя;
- более существенная обрезка отклоняется;
- увеличение разрешается только при итоговом эффективном разрешении не ниже 300 DPI;
- независимое растягивание ширины и высоты запрещено.

Коррекция выполняется в режиме `cover`: изображение пропорционально заполняет целевой формат, после чего избыток симметрично обрезается по центру.

## Ориентация

- прямой и переставленный размеры считаются одинаково допустимыми;
- заказ `4-0` не поворачивается автоматически из-за порядка размеров в имени;
- если `face` и `back` ориентированы одинаково, они остаются без поворота;
- квадратные и почти квадратные изделия сначала нормализуются по размеру и не считаются повёрнутыми из-за малой разницы сторон;
- несовпадение ориентаций сторон требует отдельной проверки;
- HTML-отчёт показывает предупреждение и превью для контроля совмещения.

## Цветовая модель

CMYK остаётся рекомендуемой моделью для печати, но RGB/sRGB больше не блокирует заказ. В отчёте появляется предупреждение, а при создании PDF цветовая модель не преобразуется.

PyMuPDF объединяет уже созданные PDF-страницы прямым копированием через `insert_pdf()` без растеризации, изменения размеров или преобразования цветов. Ghostscript сохраняется для контрольной проверки открытия и рендеринга итогового PDF.

## Установка

На macOS:

```bash
brew install python imagemagick ghostscript
python3 -m pip install -r requirements.txt
```

Проверка зависимостей:

```bash
python3 --version
magick -version
gs --version
```

## Запуск

```bash
python3 process_orders.py --input "/путь/к/папке/с/макетами"
```

### Веб-интерфейс и API

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cd frontend && npm install && npm run build && cd ..

.venv/bin/alembic upgrade head
.venv/bin/python manage.py set-password
export IMAGE_MAGIC_PASSWORD_HASH='ХЕШ_ИЗ_ПРЕДЫДУЩЕЙ_КОМАНДЫ'
.venv/bin/python control_panel.py
```

После запуска доступны:

- `http://127.0.0.1:8006/login` — вход с паролем, заданным при установке;
- `http://127.0.0.1:8006/` — единый рабочий пульт;
- `POST /api/checks` — запустить фоновую проверку папки;
- `GET /api/checks` — список запусков;
- `GET /api/checks/{id}` — состояние и результаты запуска;
- `GET /api/checks/{id}/events` — поток событий SSE;
- `POST /api/checks/{id}/cancel` — отменить проверку;
- `GET /runs/{id}/report` — интерактивный отчёт;
- `http://127.0.0.1:8006/docs` — интерактивная документация API.

Все API-маршруты, исходники, PDF и превью защищены серверной сессией.
Сессии и результаты сохраняются в `image_magic.db`; незавершённый запуск
после перезапуска помечается прерванным, а завершённая история остаётся доступна.

### PitStop Server

Интеграция выключена по умолчанию. Она использует SSH-ключ и общую папку
macOS/Windows; пароль VM в конфигурации приложения не хранится.

```bash
export IMAGE_MAGIC_PITSTOP_ENABLED=true
export IMAGE_MAGIC_PITSTOP_HOST="10.211.55.3"
export IMAGE_MAGIC_PITSTOP_PORT="22"
export IMAGE_MAGIC_PITSTOP_USERNAME="Admin"
export IMAGE_MAGIC_PITSTOP_CLI_PATH='C:\Program Files\Enfocus\Enfocus PitStop Server 23\PitStopServerCLI.exe'
export IMAGE_MAGIC_PITSTOP_PROFILE_DIGITAL='C:\Profiles\Sborka_2Corel.ppp'
export IMAGE_MAGIC_PITSTOP_PROFILE_OFFSET='C:\Profiles\Sborka_Offset.ppp'
export IMAGE_MAGIC_PITSTOP_KNOWN_HOSTS="$HOME/.ssh/known_hosts"
export IMAGE_MAGIC_PITSTOP_IDENTITY_FILE="$HOME/.ssh/id_ed25519"
export IMAGE_MAGIC_PITSTOP_MAC_SHARED_ROOT="/Users/admin"
export IMAGE_MAGIC_PITSTOP_WINDOWS_SHARED_ROOT='C:\Mac\Home'
```

Для каждого успешно собранного PDF порядок обработки такой: PitStop report-only,
сохранение JSON/XML, расчёт итогового статуса, затем production preview именно
проверенной ревизии PDF. До завершения PitStop заказ не считается готовым к
печати. Отчёты сохраняются в `output_report/pitstop/` и выдаются через
защищённые API-ссылки.

### Журнал диагностики

Сервер постоянно пишет журнал в `logs/image-magic.log`. В нём сохраняются:

- запуск, heartbeat и штатная остановка приложения;
- HTTP-метод, путь, статус, длительность и идентификатор запроса;
- стадии фоновых проверок, заказы, PDF и превью;
- ошибки Python, ImageMagick, Ghostscript и восстановление после перезапуска;
- свободное место на диске и пиковое потребление памяти.

Тела HTTP-запросов, пароли, cookie и query-параметры не записываются. Журнал
автоматически ротируется: по умолчанию хранится до 10 архивов по 10 МБ. Для
низкоуровневого сбоя Python используется `logs/image-magic-fault.log`.

Быстрый просмотр:

```bash
tail -f logs/image-magic.log
rg 'ERROR|CRITICAL' logs/
```

Настройки можно изменить переменными окружения:

```bash
export IMAGE_MAGIC_LOG_DIR="/путь/к/журналам"
export IMAGE_MAGIC_LOG_LEVEL="INFO"
export IMAGE_MAGIC_LOG_MAX_BYTES="10485760"
export IMAGE_MAGIC_LOG_BACKUP_COUNT="10"
export IMAGE_MAGIC_LOG_HEARTBEAT_SECONDS="60"
```

По умолчанию одновременно обрабатывается столько независимых заказов, сколько
ядер доступно экземпляру; до двух превью внутри каждого заказа создаются
параллельно; обычные превью исходников сохраняются до проверки PitStop.
Лимиты можно уменьшить: `IMAGE_MAGIC_ORDER_WORKERS="8"` — число одновременно
обрабатываемых заказов, `IMAGE_MAGIC_PREVIEW_WORKERS="2"` — превью на заказ.
Значение `1` отключает соответствующую параллельность. Число потоков для
заказов не может превышать число доступных экземпляру ядер.

По умолчанию панель работает с папками внутри проекта. Рабочие пути можно
настроить переменными окружения:

```bash
export IMAGE_MAGIC_ALLOWED_ROOTS="/папка/с/заказами"
export IMAGE_MAGIC_INPUT_DIR="/папка/с/заказами/входящие"
.venv/bin/python control_panel.py
```

Несколько разрешённых корней разделяются системным разделителем путей
(`:` на macOS/Linux). Исходные файлы не изменяются; результаты создаются в
`PDF`, `Previews`, `Troubles` и `output_report` внутри выбранной папки.

Направление выбирается параметром профиля:

```bash
python3 process_orders.py --input "/путь/к/папке/с/макетами" --direction digital
python3 process_orders.py --input "/путь/к/папке/с/макетами" --direction offset
```

Наборы правил находятся в `config/profiles.py`. Новое направление добавляется
как ещё одна запись в `PROFILES`, без дублирования движка проверки.

Во время запуска программа:

1. проверит и сгруппирует файлы;
2. запросит подтверждение для спорных коррекций;
3. предложит создать PDF для подходящих заказов;
4. предложит создать превью;
5. сохранит аудит и HTML-отчёт.

Результаты создаются во входной папке:

```text
PDF/                 итоговые PDF
Previews/            превью страниц
Troubles/            отклонённые файлы и причины
output_report/       интерактивный report.html
```

```bash

```

Тесты покрывают пороги размеров, эффективный DPI, подтверждения, сохранение пропорций, RGB-предупреждения, команды ImageMagick/Ghostscript и HTML-контроль ориентации.

## Безопасность обработки

- исходные изображения не изменяются;
- промежуточные файлы создаются во временной папке;
- итоговый PDF публикуется только после контрольного рендеринга;
- при ошибке весь заказ копируется в `Troubles`;
- цветовые пространства не конвертируются автоматически;
- принудительный ImageMagick resize с `!` не используется.

Подробная инструкция: [INSTALL_AND_TEST.md](INSTALL_AND_TEST.md).
