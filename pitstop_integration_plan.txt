План интеграции PitStop Server в Image Magic

1. Цель этапа
   - На этом этапе не вносим исправления в PDF.
   - Только получаем report от PitStop и на его основе определяем статус заказа:
     - Проверено
     - Предупреждение
     - На доработку

2. Где встраивать проверку
   - Лучшее место: сразу после сборки итогового PDF и перед генерацией preview/показом результата в интерфейсе.
   - Логика:
     - Images -> первичная проверка -> создание PDF страниц -> объединение PDF
     - затем PitStop report-only
     - затем превью и отображение результата
   - Так мы проверяем уже финальный PDF, который реально уйдёт дальше по процессу.

3. Формат запуска PitStop
   - На данном этапе запускаем PitStop без фикса PDF.
   - Нужно только:
     - передать итоговый PDF
     - получить report JSON/XML
   - Если PitStop находится на отдельной VM, но доступен через общую директорию, лучше использовать именно общую папку для обмена файлами.
   - CLI напрямую вызывать не нужно, если для этого нет удалённого доступа; достаточно механизма обмена файлами и запуска на той VM, где стоит PitStop.

4. Правило классификации
   - Ошибка PitStop или проблемы с чтением отчёта:
     - статус заказа = На доработку
   - Есть ошибки в report:
     - статус = На доработку
   - Есть только предупреждения:
     - статус = Предупреждение
   - Нет ошибок и предупреждений:
     - статус = Проверено
   - Приоритет статусов:
     - На доработку > Предупреждение > Проверено

5. Что хранить в данных заказа
   - Сохраняем нормализованный блок PitStop в результатах заказа:
     - execution_status
     - profile
     - pages
     - counts по ошибкам/предупреждениям/фиксам/critical/noncritical
     - список issues
     - пути к JSON/XML report
   - Это позволит в интерфейсе показать краткий итог и детали отчёта.

6. Что показать в интерфейсе
   - Статус заказа
   - Краткую сводку PitStop
   - Список найденных проблем
   - Ссылку на report
   - Пока без попытки автоматического исправления PDF

7. Порядок внедрения
   - Шаг 1: добавить парсер отчёта PitStop
   - Шаг 2: встроить вызов проверки после сборки PDF
   - Шаг 3: сохранить результат PitStop в DTO/БД
   - Шаг 4: отрисовать report в карточке заказа
   - Шаг 5: скорректировать правила статусов в backend

8. Отложено на следующий этап
   - Настройка виртуальных машин
   - Сетевые параметры
   - Автоисправление PDF через PitStop
   - Подробная схема обмена файлами между VM
