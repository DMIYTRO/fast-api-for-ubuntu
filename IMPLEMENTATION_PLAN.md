# План развития Image Magic

## Цель первого этапа

Создать локальный однопользовательский сервис допечатной проверки со следующими возможностями:

- вход только по паролю;
- единая рабочая страница после авторизации;
- интерфейс на Vue 3;
- динамическое отображение прогресса;
- сохранение запусков и результатов;
- просмотр заказов, файлов, PDF и превью;
- подтверждение спорных коррекций;
- подготовка причин возврата;
- сохранение существующей логики `BatchProcessor`;
- подготовка архитектуры к будущей интеграции с внешней CM-системой.

На первом этапе не требуются:

- регистрация пользователей;
- логины и роли;
- PostgreSQL;
- Redis;
- Celery или Dramatiq;
- несколько worker-серверов;
- непосредственная отправка действий во внешнюю CM-систему.

---

## 1. Архитектура

```text
Браузер
  ↓
Vue 3
  ↓
FastAPI
  ├── авторизация по паролю
  ├── управление проверками
  ├── SSE-обновления
  ├── выдача PDF и превью
  └── SQLAlchemy
          ↓
        SQLite

Фоновая обработка
  ├── BatchProcessor
  ├── ImageMagick
  └── Ghostscript
```

FastAPI должен заниматься быстрыми запросами и управлением состоянием. Тяжёлая файловая обработка не должна выполняться внутри HTTP-запроса.

## 2. Авторизация

### Страница входа

Отдельная страница:

```text
/login
```

На странице:

- логотип Image Magic;
- одно поле пароля;
- кнопка «Войти»;
- сообщение о неправильном пароле;
- индикатор выполнения запроса.

После успешного входа пользователь переходит на `/`.

### Хранение пароля

Пароль нельзя хранить:

- в Vue;
- в HTML;
- открытым текстом в Python;
- в репозитории;
- открытым текстом в SQLite.

Использовать Argon2-хеш из переменной окружения:

```text
IMAGE_MAGIC_PASSWORD_HASH
```

Добавить команду управления:

```text
python3 manage.py set-password
```

Она должна запросить пароль и сформировать безопасный хеш.

### Сессия

После входа FastAPI создаёт сессию:

- случайный идентификатор;
- срок действия, например 12 часов;
- запись в SQLite;
- `HttpOnly` cookie;
- `SameSite=Strict`;
- `Secure` при использовании HTTPS.

Маршруты:

```text
POST /api/auth/login
POST /api/auth/logout
GET  /api/auth/session
```

Все остальные API-маршруты и файлы требуют действующую сессию.

### Защита входа

Добавить:

- задержку после неправильного пароля;
- ограничение количества попыток;
- одинаковый текст ошибки;
- завершение старых сессий при смене пароля;
- кнопку выхода.

## 4. Единая страница после входа

Главная страница должна быть рабочим пультом, а не отдельной формой запуска.

Предлагаемая компоновка:

```text
┌─────────────────────────────────────────────────────────┐
│ Image Magic    Активная папка    Состояние       Выйти  │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Текущая проверка / последний результат                 │
│  [этап] [прогресс] [остановить] [журнал]                │
│                                                         │
├─────────────────────────────────────────────────────────┤
│ Все  | Прошли | Предупреждения | Ошибки    Поиск        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Карточки заказов                                       │
│                                                         │
├─────────────────────────────────────────────────────────┤
│ Выбрано: 3     Вернуть на доработку    Провести в печать│
└─────────────────────────────────────────────────────────┘
```

### Запуск проверки

Большую постоянную кнопку запуска убрать из центра страницы.

В верхней панели:

- показывать текущую рабочую папку;
- разместить компактную кнопку «Новая проверка»;
- открывать боковую панель или модальное окно;
- после запуска закрывать панель;
- сразу показывать ход обработки на главной странице.

### Панель новой проверки

Поля:

- путь к папке;
- выбор каталога;
- профиль цифровой или офсетной печати;
- создание PDF;
- создание превью;
- копирование проблемных файлов;
- правила обработки спорных коррекций;
- кнопка «Начать проверку».

## 5. Состояния главной страницы

### Проверка ещё не запускалась

Показать:

- выбранную рабочую папку;
- короткую инструкцию;
- кнопку «Начать первую проверку»;
- пример допустимого имени файла.

### Проверка выполняется

Показывать:

- текущий этап;
- общий прогресс;
- обрабатываемый заказ;
- количество найденных заказов;
- прошедшие и проблемные заказы;
- последние события;
- уже готовые карточки.

Первые результаты должны появляться до завершения всей папки.

### Требуется решение

Если коррекция требует подтверждения:

- обработка остальных заказов продолжается;
- заказ получает статус «Требуется решение»;
- Vue показывает параметры коррекции;
- пользователь подтверждает или отклоняет действие;
- после решения заказ возвращается в обработку.

### Проверка завершена

Показывать:

- итоговую статистику;
- карточки заказов;
- фильтры;
- превью;
- PDF;
- причины возврата;
- групповые действия;
- возможность новой проверки.

## 6. Динамическое обновление

Использовать Server-Sent Events.

Маршрут:

```text
GET /api/checks/{run_id}/events
```

Типы событий:

```text
run.started
scan.progress
order.detected
order.checked
order.waiting_confirmation
pdf.created
preview.created
order.completed
run.completed
run.failed
```

Пример:

```json
{
  "type": "order.checked",
  "run_id": "4df973b8",
  "order_id": "25506185",
  "status": "warning",
  "processed": 18,
  "total": 52
}
```

Vue обновляет только изменившуюся карточку.

### Восстановление соединения

Если SSE разорвался:

1. Показать «Восстанавливаем соединение».
2. Подключиться повторно.
3. Выполнить `GET /api/checks/{id}`.
4. Синхронизировать состояние.
5. Продолжить слушать события.

Перезагрузка браузера не должна останавливать обработку.

## 7. Разделение обработки на этапы

### Сканирование

```text
scan_folder()
```

Результат:

- найденные файлы;
- исключённые форматы;
- нераспознанные имена;
- группы заказов.

### Проверка заказа

```text
inspect_order(order_id)
```

Результат:

- размеры;
- DPI;
- цветовая модель;
- формат;
- ошибки;
- предупреждения;
- решение по ресемплингу.

### Решение оператора

```text
confirm_correction()
reject_correction()
```

Спорные файлы нельзя автоматически отправлять в `Troubles` до решения пользователя.

### Формирование результатов

```text
create_order_pdf()
create_order_previews()
save_order_result()
```

### Отчёт

Vue становится основным динамическим отчётом.

Статический HTML остаётся как экспорт:

```text
Экспортировать HTML-отчёт
```

## 8. Фоновое выполнение

Даже для одного пользователя обработка не должна выполняться внутри HTTP-запроса.

На первом этапе:

- один отдельный процесс обработки;
- одна активная проверка папки;
- очередь следующих заказов;
- FastAPI остаётся свободным;
- состояние сохраняется в SQLite.

Можно использовать отдельный процесс или контролируемый `ProcessPoolExecutor`.

Ограничения:

```text
- одна активная проверка папки;
- один или два одновременно обрабатываемых заказа;
- одна операция Ghostscript на заказ.
```

Падение ImageMagick или Ghostscript не должно останавливать FastAPI.

## 11. Карточка заказа

Карточка должна содержать:

- чекбокс выбора;
- номер заказа;
- номер клиента;
- статус;
- цветность;
- заявленный размер;
- Face и Back;
- превью с рамками;
- увеличение превью;
- визуальный поворот;
- размеры;
- DPI;
- цветовое пространство;
- формат;
- ошибки;
- предупреждения;
- подтверждение коррекции;
- причины возврата;
- дополнительный комментарий;
- ссылку на PDF.

Данные должны приходить из API, а не встраиваться в сгенерированную HTML-страницу.

## 12. Нижняя панель действий

После выбора заказов показывать закреплённую панель:

```text
Выбрано: 4

[Снять выделение]
[Вернуть на доработку]
[Провести в печать]
```

Правила:

- «Провести в печать» доступно только для прошедших заказов;
- «Вернуть» требует комментарий;
- смешанный выбор показывает доступные действия;
- перед будущей отправкой в CM появляется подтверждение;
- результат отображается отдельно для каждого заказа.

## 13. Хранение состояния

Vue хранит локально только:

- открытые карточки;
- выбранный фильтр;
- размер превью;
- предпочтение компактного вида.

Сервер хранит:

- запуски;
- результаты;
- решения;
- причины возврата;
- действия;
- прогресс;
- события.

Критические данные нельзя хранить только в браузере.
