# Аудит 01: генерация PDF

Область: от проверенного входного файла до PDF в `<input>/PDF/`. Слияние подробно разобрано в `02-merge.md`, проверка PitStop и превью здесь только упомянуты.

Метки достоверности:

- **[код]** прочитано в текущем рабочем дереве, включая незакоммиченные изменения.
- **[опыт]** воспроизведено в scratch на локальных инструментах с синтетическими файлами: ImageMagick 7.1.2-29 Q16-HDRI, Ghostscript 10.06.0, PyMuPDF 1.28.0. Реальные заказы и production VM не проверялись.
- **[предп.]** предположение, требует проверки.

## 1. Как это работает

1. Вход: `BatchProcessorAdapter.process_order` вызывается для заказа из `services/coordinator.py:807`. Если `order.passed` ложно, PDF не создаётся, файлы идут в `Troubles` (`services/batch_adapter.py:223-232`). Неподтверждённая коррекция (`ask_confirmation`) делает заказ непройденным (`processing/models.py:55-57`). [код]
2. `create_pdfs([order])` (`services/batch_adapter.py:238`) создаёт `PDF/`, выбирает порядок face/back и имя по основе имени файла face (`processing/batch_processor.py:484-490`, `:516-528`).
3. Временная папка `.{order_id}_XXXX` создаётся внутри `PDF/`, то есть на той же файловой системе, что и результат (`processing/batch_processor.py:492-495`).
4. `_build_page_refs` фиксирует ожидаемую сторону и размер каждой страницы (`:531-566`).
5. `_prepare_page_pdfs` (`:568-607`):
   - входной PDF передаётся в слияние напрямую, без ImageMagick (`:574-577`);
   - растр при `needs_resample` сначала проходит `resample_image`, затем `convert_image_to_pdf`.
6. Коррекция (`core/resampler.py:62-76`):
   ```
   magick [-define tiff:ignore-layers=true] <in> [-rotate N] -units PixelsPerInch -density <target>
     -filter Lanczos -resize WxH^ -gravity center -extent WxH <tmp>/resampled_N_side.<ext оригинала>
   ```
   Пиксели считаются из мм и `target_dpi` (300) (`:59-60`). Файл `-define` добавляется только при `tiff_layer_count == 1`. Ветка `-rotate` сейчас не работает: `_validate_file` передаёт `allow_rotation=False` (`processing/batch_processor.py:305`).
7. Конвертация (`core/pdf_exporter.py:27-36`):
   ```
   magick [-define tiff:ignore-layers=true] <in> -units PixelsPerInch -density <X>x<Y> -compress none <tmp>/N_side.pdf
   ```
   DPI равен значениям из `inspect_file` (округлены до 0,1) или `target_dpi` после коррекции (`processing/batch_processor.py:580`, `:595`).
8. Слияние: `merge_pdfs_with_pymupdf` (`core/pdf_exporter.py:79-134`) работает в процессе Python, проверяет число страниц и пишет `combined.pdf`. Выполняется и для одного входного файла.
9. Контроль: `_validate_created_pdf` (`processing/batch_processor.py:609-666`) рендерит итог через `gs -q -dSAFER -dBATCH -dNOPAUSE -sDEVICE=png16m -r72`, сверяет число страниц, размер (допуск не меньше 0,6 мм) и порядок сторон.
10. Публикация: `temporary_output.replace(output_path)` (`:509`), затем удаление временной папки при выходе из `with`.
11. Ошибка возвращается строкой в кортеже (`:511-512`). Адаптер пишет `PDF: ...`, делает превью исходников и копирует файлы в `Troubles` (`services/batch_adapter.py:244-259`).

`core/pdf_builder.py` к печатному PDF не относится: это отчёт ReportLab, вызываемый из `core/report_builder.py:248`.

Не используются в рабочем потоке [код]: `merge_pdfs_with_ghostscript`, `combine_images_to_pdf`, `should_resample`, `parse_target_dimensions_from_filename`, словарь `converted` (`processing/batch_processor.py:571`, `:605`). `core/__init__.py` их только экспортирует.

## 2. Фактические свойства результата

Проверено [опыт] на CMYK TIFF 1300x1800, 300 DPI, с ICC.

| Свойство | Результат |
| --- | --- |
| Размер страницы | Точный: 1287 px при 299,7 DPI дают 309,67 pt; округления MediaBox до целых нет |
| Боксы растровой страницы | Только MediaBox и CropBox, равные всей странице с вылетом. TrimBox и BleedBox отсутствуют, PyMuPDF подставляет MediaBox |
| ICC | Сохраняется как `ICCBased` |
| Output Intent | Отсутствует |
| Хранение пикселей | `ASCII85Decode`, без бинарного сжатия: 11,8 МБ при 9,36 МБ сырых данных, около +26 % |
| Глубина | 16-битный TIFF становится 8 бит на компонент, без предупреждения |
| JPEG | Декодируется и хранится как поток пикселей, не как исходный DCT |
| JPEG с коррекцией | Промежуточно пересохраняется как JPEG (качество 95 в опыте), то есть с дополнительной потерей |
| PNG с альфой | Создаётся SMask, PDF получает прозрачность; проверка альфы есть только для TIFF (`processing/batch_processor.py:138`) |
| RGB, Gray | Цвет не преобразуется; это только предупреждение (`processing/profile_rules.py:32-38`), заказ проходит [код] |
| Заголовок | ImageMagick пишет имя файла в `/Title`, после слияния метаданные пусты |

Нет проверки по коду, и опыт не проводился: сохранность плашечных каналов для цветности 5-x и 6-x, учёт EXIF-ориентации JPEG. [предп.] Ожидать сохранения Spot-каналов через этот конвейер нельзя, пока это не проверено на реальном файле.

## 3. Проблемы

### Высокая серьёзность

**G1. Коррекция файла с разным DPI по осям искажает и обрезает его молча.** План считается в мм (`processing/resample_policy.py:36-42`), а `-resize ^` работает с пикселями, считая их квадратными (`core/resampler.py:72`). Сценарий [опыт]: TIFF 1293x1496, 300x250 DPI, 109,5x152 мм. План: `auto_correct`, обрезка 0,50 мм. Фактически: горизонталь увеличена на 20 %, обрезано около 22 мм. Контроль размера проходит, предупреждение оператору говорит «пропорции сохранены». Исправление: нормализовать к квадратному пикселю или отклонять автокоррекцию при `dpi_x != dpi_y`.

**G2. Валидный повёрнутый PDF проходит проверку и падает на генерации.** `inspect_pdf` берёт `mediabox` без учёта `/Rotate` (`core/pdf_inspector.py:131-132`), а Ghostscript рендерит с поворотом. Сценарий [опыт]: страница 152x109 мм с `/Rotate 90` и заказ 105x148 дают `страница 1 (face) имеет размер 109.0x152.0 мм; ожидалось 152.0x109.0 мм`. Заказ уходит в ошибку и `Troubles`. Тот же результат для 109x152 с `/Rotate 90`. Исправление: сравнивать с размером с учётом поворота.

**G3. Таймаут заказа не останавливает работу, и «не принятый» результат всё равно публикуется.** Таймаут заказа 900 с (`services/coordinator.py:52`), поток продолжает работать (`:755-757`), а защита от позднего результата не срабатывает: `:811` ищет текст «не завершился за», тогда как `:788` пишет «Превышено время обработки» (нашёл этап verification, подтверждено чтением кода). Поздний результат поэтому перезапишет статус «результат не принят». `create_pdfs` также не проверяет отмену и выполнит `replace` в `PDF/` [код]. Повторный запуск в это время конкурирует с зависшим потоком за тот же `output_path`; побеждает последний `replace`. Плюс бюджеты не согласованы: двусторонний заказ с коррекцией это до 5 вызовов по 300 с, то есть 1500 с без PitStop.

### Средняя серьёзность

**G4. Причина ошибки инструмента теряется.** `check=True` без захвата stderr (`core/pdf_exporter.py:37`, `core/resampler.py:78`) даёт оператору английский текст `Command '[...]' returned non-zero exit status 1` с полными путями [опыт]. Настоящая причина уходит в stderr сервиса. Это нарушает требование AGENTS.md о понятных сообщениях на русском. Коды ошибок не классифицируются: нехватка диска, битый файл и запрет политики выглядят одинаково.

**G5. После неудачной перегенерации остаётся старый PDF.** Сценарий [опыт]: PDF создан, исходник испорчен, повторный запуск вернул ошибку, старый файл лежит на месте без изменений. Адаптер не вернёт `pdf_path`, поэтому статус заказа корректен, но человек или внешний процесс, читающий `PDF/`, увидит устаревший файл. По коду в репозитории автоматического потребителя такого файла не найдено; внешние не проверялись.

**G6. Нет привязки к проверенному исходнику.** Между инспекцией и генерацией файл не сверяется (нет хеша, размера, mtime). Подмена с другим физическим размером ловится контролем [опыт]; подмена того же размера, по коду, пройдёт незаметно. Риск выше при ожидании подтверждения оператора, когда пауза неограниченна, и при незавершённой загрузке в общую папку.

**G7. Контроль итога проверяет геометрию, но не содержимое.** Цвет, ICC, глубина, пустота страницы и совпадение картинки не сверяются [код]. Предупреждения Ghostscript игнорируются: при `Page drawing error` код возврата был 0 [опыт], спасает только сверка числа страниц.

**G8. CropBox и TrimBox не участвуют в проверке размера.** Страница с CropBox 100x100 pt внутри MediaBox 109x152 мм прошла весь конвейер [опыт]: `gs` без `-dUseCropBox` рендерит MediaBox. Видимая в просмотрщике область и проверенная отличаются. TrimBox также не сравнивается с размером из имени.

**G9. Ресурсы не ограничены и временные файлы ImageMagick не изолированы.** Для превью `TMPDIR` и `MAGICK_TEMPORARY_PATH` заданы (`core/preview_generator.py:214-215`), для генерации нет [код]. По умолчанию заказов параллельно столько, сколько ядер (`services/coordinator.py:39-47`). Лимит входа 2000 МБ (`config/profiles.py`). Локальный `policy.xml` лимитов не показал; production не проверялся. Без сжатия страница весит сырой объём плюс 26 %, и на диске `PDF/` одновременно лежат страницы и `combined.pdf`, то есть более 2,5 объёма итога. Для A0-формата при 300 DPI в CMYK это уже около 2 ГБ на страницу (расчёт).

**G10. Слияние PyMuPDF идёт без таймаута внутри процесса.** Таймаут `run_command` его не покрывает. [предп.] Большой файл нагружает память веб-процесса и может удерживать GIL; поведение под нагрузкой не измерялось.

**G11. Допуски разные для одной и той же проверки.** Растр: 0,1 мм как погрешность (`config/profiles.py`), PDF: 0,5 мм (`processing/batch_processor.py:375-376`), контроль итога: 0,6 мм (`:654`). Файл, не прошедший строгую проверку, становится коррекцией только в растре; для PDF коррекции нет.

**G12. 16-битные данные и повторное JPEG-сжатие происходят молча.** См. таблицу. Если заказчик требует «без потерь», это не выполняется.

**G13. Повышение разрешения.** Файл с эффективными 250 DPI при коррекции интерполируется до 300 (`target_dpi`), а тот же файл без коррекции остаётся 250. Изменение `min_dpi` на 250 не закоммичено. Отчёт сообщает DPI источника, а не факт интерполяции.

### Низкая серьёзность

**G14. Таймаут убивает только прямой процесс.** `start_new_session=True` создаёт группу, но `subprocess.run` завершает лишь дочерний PID (`core/tool_runner.py:41-46`). Опыт с `sh -c 'sleep & wait'` оставил потомка живым. Для этих команд `magick` и `gs` потомков, по наблюдению, не создают, но заявление в docstring об изоляции верно лишь частично.

**G15. Символ `%` в пути ломает контроль.** Ghostscript трактует его в `-sOutputFile`; опыт дал ошибку рендера с кодом 0, значит оператор увидит «в итоговом PDF 0 страниц». Символы `[ ]`, `%`, `*`, `:`, `#` в имени существующего входного файла для `magick` проблем не дали [опыт].

**G16. После SIGKILL или рестарта остаются папки `.{order_id}_*` в `PDF/`.** Очистки нет [код]. Сканер не рекурсивен и их не видит (`processing/batch_processor.py:83-86`), но место занято.

**G17. Нет fsync перед `replace`.** Атомарность верна для локальной ФС. [предп.] Поведение на SMB или NFS (`/mnt/shared`) не проверялось; нужен тест у stability.

**G18. Устаревшие тексты.** `core/resampler.py:1-8` описывает условие, которого в потоке нет; `processing/batch_processor.py:620` называет Ghostscript создателем файла; `core/pdf_exporter.py:49` советует `brew` на Linux; docstring `:569` «keep incoming PDFs untouched» неточен, так как страницы пересобираются PyMuPDF.

## 4. Что работает надёжно

- Публикация атомарна в пределах одной ФС, частичный PDF в итоговое имя не попадает [код].
- Временные файлы удаляются при обычной ошибке [опыт].
- Команды запускаются списком аргументов, без shell [код].
- Страницы растеризуются только из исходного растра; входные PDF не проходят через ImageMagick [код].
- Исходные файлы не изменяются [код].

## 5. Улучшения стабильности по приоритету

1. Закрыть G1 и G2, это ошибки логики, не зависящие от callas.
2. Захват stderr, классификация ошибок, сообщения на русском (G4).
3. Токен отмены перед `replace` и единый бюджет времени (G3). Публикация только при актуальном токене запуска.
4. Хеш исходника при инспекции и сверка перед генерацией (G6).
5. Удаление или перевод в статус устаревшего PDF при неудачной перегенерации (G5).
6. Отдельный `MAGICK_TEMPORARY_PATH`, лимиты `-limit memory/map/disk`, проверка свободного места (G9).
7. Заменить `-compress none` (ASCII85) на Zip без потерь, если заказчик подтвердит допустимость.
8. Вывести слияние в отдельный процесс с таймаутом (G10).
9. Записывать TrimBox и BleedBox для растровых страниц из значения вылета профиля.
10. Очистка забытых временных папок при старте, с учётом возраста (G16).

## 6. Что заменяется в callas

Возможности callas ниже подлежат подтверждению этапом callas; здесь указано только, что заменяется в коде.

| Шаг | Сейчас | Кандидат в callas | Комментарий |
| --- | --- | --- | --- |
| Растр в PDF | `convert_image_to_pdf` | Заменяемо | Нужна проверка DPI, ICC, боксов |
| Коррекция размера | `resample_image` | Отдельное решение | Правила `analyze_resample` принадлежат приложению, их лучше оставить |
| Слияние | `merge_pdfs_with_pymupdf` | Заменяемо | Сохранение Output Intent, см. `02-merge.md` |
| Контроль итога | `_validate_created_pdf` | Частично | Инвариант приложения (страницы, порядок, размер) лучше оставить независимым |
| Публикация | `replace` | Остаётся в приложении | Результат с другого сервера требует своей схемы атомарности |
| Запуск инструмента | `run_command` | Новый транспорт | Таймаут, отмена, stderr, повтор |

На сервере callas меняются исходные условия: файлы надо передавать или разделять через общую папку, поэтому G6 и G17 становятся важнее. Таймаут на стороне клиента не остановит задачу на удалённом сервере, поэтому G3 требует явного протокола отмены.

## 7. Что требует решения заказчика

1. Что значит «без изменений»: допустимо ли 8 бит вместо 16, Zip вместо ASCII85, повторный JPEG.
2. Нужны ли TrimBox, BleedBox и Output Intent в итоговом PDF, и какой профиль вывода.
3. RGB и Gray: блокировать, конвертировать через callas или оставлять предупреждением.
4. Прозрачность в PNG: блокировать или сводить.
5. Плашки White и Clear (цветность 5-x, 6-x): как они приходят и как должны попасть в PDF.
6. Должен ли callas исправлять PDF или только проверять. Исправление создаёт новую ревизию, отличную от проверенной.
7. Судьба `min_dpi=250`: незакоммиченное изменение и порядок повышения разрешения.
8. Нужен ли резервный путь на ImageMagick при недоступности сервера callas.
9. Как трактовать входной PDF с CropBox меньше MediaBox и с TrimBox, не совпадающим с именем файла.

## 8. Ограничения аудита

Опыты проведены на синтетических файлах и локальных версиях инструментов. Версии на production, его `policy.xml`, скорость `/mnt/shared` и реальные заказы не проверялись. Тесты репозитория не запускались, сервисы не трогались.
