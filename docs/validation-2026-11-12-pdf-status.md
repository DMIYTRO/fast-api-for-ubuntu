# Проверка изменений статусов PDF, 12 ноября 2026

Ветка: `Admin/perf-jobid-inspect-sborka`. Production и исходные файлы не менялись.
Архивная сессия Claude и её worktree использовались только для чтения.

## Итоговое поведение

- Только зелёный результат находится в `PDF/Print`; читаемый результат с замечаниями — в `PDF/Rework`, техническая ошибка — в `PDF/Failed` (когда PDF удалось сохранить).
- Исправление Callas перепроверяется сразу после принятия: размеры, страницы, DPI, цвет, настроенный PitStop. Переходы между папками, повторное исправление, сбой финального переименования и сбой записи БД покрыты регрессиями. Старые замечания исходников сохраняются исторически, текущие группы берутся из `revision_check`.
- Локальные замечания не прекращают PitStop, если можно собрать читаемый диагностический PDF. Причина пропуска показывается оператору.
- Повторы сгруппированы по типу. Объекты считаются по уникальным страницам и координатам; при неполных координатах показывается число записей.
- Красочность callas хранится по страницам и документу; измерения среднего покрытия отделены от TAC. Пороги задаются профилем/настройками, 20/250 — примеры. После смены PDF старые флаги сбрасываются.
- TIFF проходит через отдельную плоскую копию сохранённого видимого композита. Успешная операция отмечается в DTO и карточке. Настоящий многостраничный TIFF не смешивается со слоями.
- Журнал действий доступен в карточке и через API; выполненные операции отделены от запланированных.
- Кнопка размера запускает только `size_correction`, даже если сервер предлагает другие планы.
- PSD: исследование, отдельный прототип и benchmark. Автоматический приём в основной конвейер не включён; сложные Photoshop-эффекты требуют реальных эталонов.

## Два исходных падающих теста

Оба обнаружили устаревшие ожидания; рабочее поведение сохранено:

1. `ControlPanelTests.test_order_files_and_prepared_actions_round_trip_through_api`: возврат уже выполнялся синхронно и возвращал `prepared`, а тест ожидал `pending`.
2. `ControlPanelTests.test_layered_tiff_export_is_separate_and_scoped_to_order`: POST фонового экспорта возвращает `processing`; завершение проверяется отдельным GET, а тест ожидал `completed` сразу в POST.

Сетевой скрипт перенесён из корня в `scripts/sborka_orderinfo_fetch.py`, чтобы pytest не обращался к Sborka при сборе тестов. Тест локального корпуса пропускается при отсутствии не хранимых в Git файлов.

## Проверки инструментов

ImageMagick/Ghostscript запускались реально: сборка и рендер PDF, видимые/скрытые слои, многостраничный TIFF, CMYK, 16 бит, DPI, ICC, неизменность источников, PSD-прототип. Измерения PSD benchmark и ограничения приведены в отдельном исследовании.

PitStop и callas проверялись фейками и отчётами из fixtures. Живые серверы в этой сессии не вызывались; production не перезапускался. Проверка реального заказа после согласованного деплоя остаётся отдельным шагом.

Карточка проверена браузером Orca на синтетическом payload (группы, значки TIFF/красочности, подробности, журнал). Снимок экрана не получен: захват дважды завершился тайм-аутом отсутствующего кадра браузера.

`frontend/dist` после сборки возвращён к исходному состоянию: перед деплоем требуется собрать frontend в целевом checkout.
